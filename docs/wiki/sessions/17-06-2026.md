# Summary

Phase 4: fit the copied API to the lite stack with four small changes — dropped
the inline `sharp` dependency (avatars/covers now convert via image-svc
`POST /convert`), added a real 8 GiB storage hardcap at chapter-import admission
(`507`), and mounted the 9 business handlers under `/api/v1` (ops endpoints stay
at root). The outbox + dispatcher + Redis streams + worker event contract are
untouched. Storage→R2 is env-only (no code change, per §7.1).

Plan: `LazyScan-Stack/.hermes/plans/2026-06-17_173000-lazyscan-lite-concrete.md`
§7 (task `..._phase-4-api.task.md`).

# Files Touched

- `api/src/env.ts` — added `IMAGE_SVC_URL` (default `http://image-svc:8001`) and
  `STORAGE_QUOTA_BYTES` (default 8 GiB) to the schema (both were already in
  `.env.example` but unvalidated/ignored).
- `api/src/config.ts` — surfaced `imageSvc.url` + top-level `storageQuotaBytes`.
- `api/src/shared/upload/image.ts` — removed `import sharp`; `processImageBuffer`
  now POSTs raw bytes to `{IMAGE_SVC_URL}/convert?w=&h=&q=`, decodes base64 webp,
  maps `422→INVALID_IMAGE` / other-non-ok→`502`. Signatures unchanged → the 3
  upload.service callers untouched. Config read lazily + memoized (keeps the
  pure size-limit unit test env-free).
- `api/src/shared/http/error.ts` — `insufficientStorage()` helper (`507`).
- `api/src/modules/chapter/chapter.repository.ts` — `sumReadyPageBytes()`.
- `api/src/modules/chapter/chapter.service.ts` — quota gate in
  `createChapterImport` (after ownership, before staging/outbox): `used +
  incoming > storageQuotaBytes` → `507 STORAGE_QUOTA_EXCEEDED`.
- `api/src/app.ts` — wrapped the 9 handlers in `new Elysia({ prefix: "/api/v1" })`;
  `/health` + `/metrics` + logger/rateLimit/auth/metrics hooks stay on root.
- `api/package.json` / `bun.lock` — `sharp` removed.
- `web/src/api/client.ts` — `API_BASE = "/api/v1"`, `fetch(API_BASE + path)`.
  Presigned R2 PUT (`chapter.ts`) stays raw.
- `api/src/test/api.smoke.test.ts` — paths prefixed to `/api/v1` at the
  `requestJson` chokepoint (`/health` exempt) + the raw avatar `Request`; added a

- `docs/wiki/{known-constraints,architecture}.md` — `/api/v1` mount, sharp drop →
  image-svc coupling, quota gate, `STORAGE_PROVIDER=s3` deploy note.

# Previous Behavior

Avatars/covers processed inline with `sharp`; `STORAGE_QUOTA` was a phantom env
(never read) so no real byte cap; business routes mounted at root (`/auth`,
`/manga`, …) and the frontend hit those bare paths.

# New Behavior

No `sharp` in the API — all sync image conversion goes to image-svc `/convert`
(webp, 10 MB cap shared). `STORAGE_QUOTA_BYTES` is enforced (`507` over cap).
Business routes are `/api/v1/...`; `/health` + `/metrics` stay at root. The web
client prefixes every call once.

# Reason For Change

Plan §7 — shrink the API to the lite stack without touching the proven async
pipeline (outbox/dispatcher/streams) or the API↔worker event contract.

# Risks

- **Route paths moved to `/api/v1`** — a breaking change for any external API
  consumer, but the web client is updated in the same change and nothing is
  deployed yet (phased assembly). nginx (Phase 5) proxies the `/api` prefix.
- **New runtime coupling:** avatar/cover upload now needs image-svc reachable
  (`502` if down). Chapter pages were already async, unaffected.
- **Quota undercounts** (only `ready` pages carry `size_bytes`); the 2 GB margin
  + storage prune absorb staged/in-flight originals.
- Elysia nesting verified safe: handlers self-resolve `user` from the cookie
  (`resolveRequiredUser`/`requireAuth`), not the root derive; root hooks reach
  the deeper group (scope = self + descendants).
