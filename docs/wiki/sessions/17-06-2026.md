# Summary

Phase 1 of the LazyScan-lite rewrite: scaffolded the monorepo from the four
source trees, wrote `docker-compose.yml` + `.env.example`, centralized the wiki,
and consolidated agent instructions into one root `AGENTS.md`. No service code
stripped, built, or modified — that is Phases 2–5.

Plan: `LazyScan-Stack/.hermes/plans/2026-06-17_173000-lazyscan-lite-concrete.md`
(Phase 1 task: `..._phase-1-scaffold.task.md`).

# Previous Behavior

Empty repo (LICENSE only). The four services lived as separate sibling repos
under `LazyScan-Stack/` (Kiln, Herald, LazyScan/api, LazyScan/web), each with its
own `docs/wiki/` and (Kiln/Herald) its own `AGENTS.md`.

# New Behavior

Single monorepo. Six-container compose pipeline defined (postgres, redis,
image-svc, mail-svc, api, web). One centralized `docs/wiki/`. One root
`AGENTS.md`. Per-service worker contracts folded into `docs/wiki/modules/`.

# Reason For Change

Compact the working stack into one deployable repo (R2 + nginx, dropping MinIO +
Aegis + observability). Phase 1 lays the skeleton so later phases strip/repoint
in isolation.

# Risks

- Module docs (`image-svc.md`, `mail-svc.md`) describe **pre-strip** code (still
  carry Prometheus/OTel). Phases 2–3 must update them when stripping → drift
  watch noted in `known-constraints.md`.
- `web/nginx.conf` was copied from the Aegis-era source; Phase 5 (§8.1)
  replaces it. Not yet reconciled.
- No build/run validation beyond `docker compose config -q` (parse only).
