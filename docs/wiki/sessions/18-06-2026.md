# Summary

P0 from `approved-to-implement.md` — enforce rate limiting on the live public
deploy. Inspection found the doc's premise wrong: the limiter was not merely
"off and mis-keyed" but **inert** — two compounding Elysia bugs meant neither
`globalRateLimit` nor `authRateLimit` ever fired. Fixed the middleware, split
the auth bucket, added a public-read burst cap, wired the proxy/env plumbing,
and exempted `/health`.

# Files Touched

- `api/src/middleware/rate.limit.ts` — extracted the fixed-window check into a
  reusable `enforceRateLimit(ctx, opts)`; `globalRateLimit` now uses
  `{ as: "global" }` + `seed:"global"`; added `authStrictLimit`/`authLooseLimit`/
  `publicReadLimit` route-level limiters with distinct `keyPrefix` buckets.
- `api/src/config.ts` — `staticConfig.rateLimit` extended: `auth.strict {5,15m}`,
  `auth.loose {20,15m}`, `publicRead {60,1m}`.
- `api/src/modules/auth/auth.handler.ts` — dropped group-level `.use(authRateLimit)`;
  register/resend → `authStrictLimit`, verify-email/login → `authLooseLimit` (route
  `beforeHandle`).
- `api/src/modules/{manga,reader,profile}.handler.ts` — `publicReadLimit` on the 9
  public GETs (catalog/reader/profile).
- `api/src/app.ts` — moved `/health` above `.use(globalRateLimit)` so monitor
  checks aren't throttled (they share one proxy-IP bucket).
- `api/src/env.ts` — corrected the `TRUST_PROXY` comment (drift: nginx now fills
  `X-Real-IP` from `CF-Connecting-IP`).
- `web/nginx.conf` — `real_ip_header CF-Connecting-IP` + `set_real_ip_from
  0.0.0.0/0` (server scope) + `proxy_set_header X-Real-IP $remote_addr` on `/api/`.
- `docker-compose.yml`, `.env.example` — forward + default `ENABLE_RATE_LIMIT`,
  `TRUST_PROXY`.

# Previous Behavior

Limiter present but never executed. Root causes (both verified against Elysia
1.4.29, empirically):
1. **Scope** — `.onBeforeHandle(fn)` defaults to `local` scope; a plugin's local
   hook is stripped (`filterGlobal`) when `.use()`d into a parent, so it fired for
   zero routes. (The codebase already half-knew this — `app.ts` puts metrics on
   root for the same reason.)
2. **Dedup** — every instance shared `name:"rateLimit"` with no `seed`; Elysia
   dedupes by `name+seed`, so the auth limiter was dropped against the global one.

Even with `ENABLE_RATE_LIMIT=true`/`TRUST_PROXY=true` the flags would have toggled
a no-op. Per-client keying was also dead (read `x-real-ip`, but nginx set only
`X-Forwarded-For`, and the real client is in `CF-Connecting-IP`).

# New Behavior

- Global 100/15min on all routes (`/metrics`, `/health` exempt by definition
  order). Auth: strict 5/15min (register+resend), loose 20/15min (verify+login).
  Public reads: 60/1min burst cap. All keyed on the real client IP in production.
- Algorithm unchanged: fixed-window counter (boundary doubling accepted — adequate
  for scraping/SMTP-abuse on a lite self-host; matches the global limiter).

# Reason For Change

Site is public with a paid SMTP relay behind auth; the limiter was inert →
open to email-bomb and credential brute-force. P0.

# Risks

- **VPS skip-worktree compose override** (see prior entry): the canonical
  `docker-compose.yml` env-forward change will NOT reach the VPS via `git pull`.
  Operator must mirror `ENABLE_RATE_LIMIT`/`TRUST_PROXY` into the VPS-local compose
  AND set both `=true` in the VPS `.env`. `web/nginx.conf` ships in the image build
  (not skip-worktree) so it deploys normally. VPS web is `127.0.0.1:8081` — still
  localhost-bound, so `set_real_ip_from 0.0.0.0/0` stays safe.
- `set_real_ip_from 0.0.0.0/0` trusts `CF-Connecting-IP` from any peer; safe ONLY
  because the web port is `127.0.0.1`-bound and reachable solely via cloudflared.
  If ever exposed directly, the header becomes spoofable.
- Heavy legit binge-readers could approach the 60/1min public burst cap; tune in
  `config.ts` if observed.

# Notes

- Verification: `bun run typecheck` clean; runtime probes confirmed
  enabled→429 (+Retry-After), disabled→200 (gate holds), global-scope fires for
  siblings, scoped/seeded buckets isolate, parent `onError` catches route-hook
  throws. Integration smoke suite not run here (needs the docker stack; it sets

- A focused unit test for `enforceRateLimit` (no DB needed) is worth adding —

- CodeRabbit review (`-t uncommitted`): 1 critical — F-005, the pre-existing
  `"unknown"` IP fallback collapsing to one bucket (unreachable in this deploy).
  Hardened to fail-closed (R-005); re-review clean (0 findings).
