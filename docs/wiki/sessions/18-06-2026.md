  `ENABLE_STORAGE_PRUNE`, so `.env=true` was ignored and prune logged disabled.
  Added `ENABLE_STORAGE_PRUNE: ${ENABLE_STORAGE_PRUNE:-false}`.
- (Phase 5 edge commit `13060ec`, prior session) also fixed the related
  `STORAGE_PROVIDER` forwarding gap — same class.

# Previous Behavior

In-container web build broke on the missing asset; api boot crashed on an
unmigrated DB; storage prune silently off despite `.env`.

# New Behavior

`docker compose up -d --build` brings the stack up clean: web builds, api
migrates-then-serves, prune honors `.env`. All three are the same root cause —
**compose/Dockerfile not forwarding what the code/build needs** (env vars not in
the `environment:` block never reach the container).

# Reason For Change

Make the committed stack actually deployable. The fixes align the code with
AGENTS.md ("migrations run at API boot" is now true) and the env.ts intent
("bundled compose turns prune on").

# Risks

- api auto-migrate runs on every boot — idempotent via `schema_migrations`
  (single api replica; safe). `exec` preserves graceful shutdown.
- Fixes are committed to canonical files; the VPS runs a **local, skip-worktree
  compose override** (see Notes) so `git pull` won't clobber it.

# Notes

VPS-specific topology (operator deviations from the canonical self-contained
compose — kept VPS-local, uncommitted, `git update-index --skip-worktree`):

- **Shared Postgres** (`shared-postgres`, `postgres:16-alpine`, network
  `shared-db`) reused instead of the bundled service. Pre-created `lazyscan`
  db + role + `pg_trgm` (superuser, since migration 013/015 need the extension
  and the role isn't superuser on a shared instance). Compose drops the
  `postgres` service, points the 3 `DATABASE_URL`s at `shared-postgres:5432`,
  joins `shared-db` as `external`.
- **Web on `127.0.0.1:8081`** (dozzle holds 8080).
- **Cloudflare Tunnel** is `sanctuary.my.id`-scoped, but `lazyscan.my.id` apex is
  served by the same tunnel via a **manual proxied CNAME** (`@` →
  `<tunnelID>.cfargotunnel.com`) + ingress `hostname: lazyscan.my.id` →
  `127.0.0.1:8081`. `cloudflared tunnel route dns` misfired (appended the wrong
  zone) because the cert is scoped to the other zone — manual DNS bypasses it.
- **SMTP (Sumopod / kirim.email):** sending requires sender-domain auth — relay
  returned `450 Custom sender domain missing auth credentials` until
  `lazyscan.my.id` was verified (sumo-verification TXT + SPF
  `include:spf.kirim.email`). DKIM not yet added (OTPs may spam-land). OTP code
  never logged — contract held (`verification email handled`, no code).
- Images served from `cdn.lazyscan.my.id` (R2 custom domain); app is apex-only.
